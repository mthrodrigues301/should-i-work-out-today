## Editorial brief

- Three separate carousels per day in publishing order: English (en), bilingual English + PT-BR (bi), Portuguese (pt). The bilingual carousel must include both languages on its cover and every slide, with a bilingual caption. Portuguese must be understandable in Portugal.
- Fixed cover sequence: cream #f1efe8 → lime #eaff38 → black #11110f. The renderer offsets internal slide colors by post so covers never all have the same background. The bilingual post is always second. In the default newest-first grid, the trio appears reversed: black / lime bilingual / cream. Check current grid alignment and pinned posts when connecting; existing posts and pins can affect row alignment.
- Audience: workout motivation and sustainable consistency. English prioritizes the US; Portuguese prioritizes Brazil with Portugal as secondary audience.
- 4–6 slides: hook, practical idea, small action, question or save/share CTA. One clear topic each day, localized naturally in both languages.
- Alternate themes: starting, planning, consistency, making time, avoiding comparison, adapting goals, community and recovery. Avoid repeated hooks from the previous 30 batches.
- Do not invent studies, testimonials or guarantees, prescribe exercise through injury, or imply that recovery is failure. Prefer original motivational copy over attributed quotations.
- Preserve existing social identity: cream #f1efe8, ink #11110f, lime #eaff38, bold Arial/Helvetica as in the previous feed assets, arrow mark, large short headlines and generous whitespace. Existing website uses Anton; the existing feed uses Arial bold.

## Daily production

### Local app references — source of truth

Before creating each batch, consult the existing local app, not only old social images:

- `src/styles/main.css`: `:root` defines light ink #11110f, paper #f1efe8, accent #eaff38 and muted #77766f. Dark theme defines paper #0c0d0b, ink #f0eee7 and muted #999a92. Do not confuse the light ink color with the dark background.
- `.brand` and `.brand-mark`: compact stacked brand and rounded lime arrow tile; use the actual logo from `public/assets/images/favicon.svg` as the reference.
- `.eyebrow`: small uppercase label, tracking and thin divider.
- `h1` and `#message`: oversized Anton headline with tight spacing; bold supporting sans-serif text. The existing social feed uses bold Arial/Helvetica, and the app's Story renderer uses Impact for the large answer. Preserve this distinction instead of claiming they share one font.
- `.share-cta`, `.next-button` and `.instagram-cta`: lime emphasis, rectangular outlines and arrow affordances. Adapt these into static visual cues; do not depict a working button on a carousel.
- `src/scripts/app.js`, Story canvas rendering: logo, editorial hierarchy, theme colors, attribution and footer/domain placement. Adapt 1080 × 1920 Story proportions to 1080 × 1350 feed cards rather than cropping.
- `src/index.html` and `src/locales/en.js` / `pt.js`: actual component labels, product features and voice. Verify any feature mentioned in a post against the implementation.

The app source takes priority for brand changes. Existing social assets remain the reference for the established feed composition. If either changes, update the carousel template intentionally and visually review the result.

1. Read this brief and the last 30 `social/instagram/daily/*/content.json` files. Select a new topic.
2. Create a JSON input following `instagram/example.json`, with the current date in America/Sao_Paulo. Do not reuse the example's copy daily.
3. Run `node scripts/instagram/render.mjs <input.json>` from the project. The renderer validates all three posts before creating JPEGs at 1080 × 1350, captions, a preview, and a manifest. A completed batch is never overwritten automatically.
4. Open the preview and inspect every slide for clipping, accents, readability and consistency. If a batch is incomplete, repair it; never claim creation based solely on existing files. Review `manifest.json` and actual images.
5. Write `qa.json` in that batch folder with reviewed timestamp and result. The renderer mirrors only the JPEGs and manifest into `public/social/instagram/daily/<date>/`, which is the public HTTPS source for Meta after deployment.
6. Commit and deploy that prepared batch before its first publication slot. Batch creation and QA are not proof of publishing.
7. Report completed assets with a preview link; notify failures or required action. Do not repeat unchanged connection warnings every day.
